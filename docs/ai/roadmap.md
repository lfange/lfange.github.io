# 从入门到进阶：12 周学习路线

这条路线面向有基础编程能力的学习者。目标不是在 12 周内“精通所有 AI”，而是完成一个可以评测、部署、观测和解释的端到端项目，并具备继续深入某一方向的基础。

## 开始前的准备

- 熟悉一种编程语言，推荐 Python；能读写 JSON、调用 HTTP API。
- 具备 Git、命令行、容器和基础 Linux 使用能力。
- 掌握基础概率、线性代数和微积分概念；应用方向不必先推完整公式。
- 准备一个小而真实的业务问题，不要以“做一个万能聊天机器人”为目标。

## 12 周主线

| 周次 | 主题         | 学习与实践                                          | 本周交付物                |
| ---- | ------------ | --------------------------------------------------- | ------------------------- |
| 1    | AI 基础      | ML / DL / Transformer、Token、Embedding、训练与推理 | 概念图与模型对比实验      |
| 2    | 模型 API     | 提示词、结构化输出、错误处理、成本                  | 可校验 JSON 的小应用      |
| 3    | 评测         | 构建真实样本集、指标、错误分类                      | 50 ～ 100 条基线评测集    |
| 4    | RAG          | 文档解析、分块、检索、重排、引用                    | 可追溯来源的知识问答      |
| 5    | 数据工程     | 清洗、去重、标注、版本、泄漏检查                    | 数据卡与版本化数据集      |
| 6    | 微调         | SFT、LoRA / PEFT、训练日志与回归                    | 小模型 Adapter 与评测报告 |
| 7    | 工具与工作流 | 工具契约、权限、幂等、确定性编排                    | 带审批的业务工作流        |
| 8    | Agent        | Agent 循环、状态、预算、停止条件                    | 有边界的单 Agent 原型     |
| 9    | 推理服务     | 量化、批处理、延迟与吞吐测试                        | 服务基准与容量报告        |
| 10   | LLMOps       | Trace、版本、发布门槛、灰度与回滚                   | 评测流水线与观测看板      |
| 11   | 安全治理     | 注入、隐私、供应链、红队                            | 威胁模型与红队报告        |
| 12   | 综合发布     | 端到端测试、文档、演示与复盘                        | 可部署作品和项目说明      |

每周都保留同一份核心评测集。这样可以看到每项技术是否真的改善了结果，而不是只完成了一个新功能。

## 综合项目：企业知识与任务助手

选择一个你有权使用的文档集合，例如产品手册、技术规范或个人笔记，构建：

1. 文档采集、解析、分块、版本和删除流程。
2. 关键词 + 向量的混合检索，回答附带精确来源。
3. 一个只读工具，例如查询工单或项目状态。
4. 一个有副作用的工具，例如创建申请；必须二次确认并保证幂等。
5. 离线评测集，覆盖正常、缺少证据、权限不足和恶意输入。
6. 端到端 Trace、质量 / 延迟 / 成本看板。
7. 灰度、限额、降级和回滚方案。
8. 威胁模型、数据卡、模型卡或系统卡。

最终演示不只展示成功案例，还要主动展示：检索不到时如何拒答、注入攻击如何被限制、工具失败如何恢复、版本如何回滚。

## 按方向深入

### AI 应用工程师

重点学习 API 设计、结构化输出、RAG、搜索、缓存、工作流、Agent、可观测性和安全边界。继续完成 [AI Agent 专栏](../ai-agent/README.md)。

### 模型 / 算法工程师

深入优化、损失函数、Transformer、数据配比、分布式训练、SFT、偏好优化、量化和评测。复现小规模论文结果，并严格记录实验。

### 推理 / 平台工程师

深入 GPU 架构、CUDA、算子、KV Cache、调度、并行、容器、Kubernetes、网络和容量工程。对同一模型建立可重复的性能基准。

### 数据与 LLMOps 工程师

深入数据仓库、流批处理、数据质量、血缘、实验跟踪、注册表、CI / CD、OpenTelemetry、灰度和成本治理。

### AI 安全与治理

深入应用安全、隐私工程、供应链、红队、模型风险、审计与行业监管。把政策要求转化为可以测试和监控的工程控制。

## 能力检查表

### 入门

- 能解释训练、推理、Token、Embedding、上下文窗口和幻觉。
- 能调用模型并验证结构化输出。
- 能建立小型评测集，而不是凭感觉比较结果。

### 熟练

- 能在提示词、RAG、工具和微调之间做合理选择。
- 能分析质量、延迟、吞吐、成本和安全的权衡。
- 能建立版本链、Trace、灰度和回滚机制。

### 进阶

- 能从失败样本定位数据、模型、检索、工具或策略问题。
- 能设计分布式训练或推理架构，并用真实负载验证容量。
- 能把风险要求落实为权限、评测、审批、监控和事故响应。
- 能清晰说明系统适用范围、已知限制和退出机制。

## 项目验收标准

| 维度   | 合格标准示例                             |
| ------ | ---------------------------------------- |
| 价值   | 有明确用户、任务和成功定义，不是技术演示 |
| 质量   | 使用冻结评测集，有总体和关键切片指标     |
| 可靠性 | 超时、重试、降级、幂等和回滚经过测试     |
| 性能   | 给出 P50 / P95 延迟、吞吐和目标容量      |
| 成本   | 计算单位成功任务成本，并设置预算上限     |
| 安全   | 有威胁模型、最小权限、红队和人工审批点   |
| 治理   | 数据、模型、提示词和发布版本可追溯       |
| 文档   | 新成员可以复现实验并部署系统             |

## 学习方法

- **先做基线，再学技术**：没有基线，就无法判断复杂方案是否有效。
- **围绕失败样本学习**：每周选最常见的失败类型，针对性补知识。
- **优先读官方文档与论文**：二手教程适合入门，但版本和结论可能过期。
- **固定问题，逐步加复杂度**：同一项目更容易看清技术的真实收益。
- **写决策记录**：说明为什么选、有哪些替代、如何验证、何时重新评估。

当你能把一个 AI 系统的目标、数据、模型、评测、部署、成本和风险讲清楚，并能用证据证明它达到门槛时，才算真正跨过了“会调用模型”的阶段。
