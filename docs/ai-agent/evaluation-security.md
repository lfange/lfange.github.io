# 评测与安全

对 Agent 来说，“回答看起来不错”不是可用的质量标准。它可能给出漂亮的文字，却用错了工具、跳过审批、引用了错误证据或付出十倍成本。

评测与安全要贯穿开发全过程，不是上线前最后加一个敏感词过滤器。

## 1. 评测的四个层次

| 层次 | 要评什么               | 例子                                     |
| ---- | ---------------------- | ---------------------------------------- |
| 组件 | 单次模型、检索器或工具 | 参数解析正确率、Recall@k                 |
| 轨迹 | 过程是否合理           | 是否选对工具、是否少走弯路               |
| 结果 | 最终任务是否完成       | 事实正确、引用完整、格式合规             |
| 系统 | 生产环境是否值得运行   | 完成率、P95 延迟、单任务成本、人工接管率 |

只评最终答案会掩盖“这次恰好成功”的脆弱路径；只要求轨迹完全一致，又会错杀合理的新解法。更好的方式是检查关键不变量：必须查到真实数据、不能调未授权工具、写入前必须经过审批。

## 2. 建立可回归的评测集

每个样本不应只有“问题 + 标准答案”：

```ts
type EvalCase = {
  id: string
  input: string
  fixture: Record<string, unknown>
  expected: {
    outcome?: Record<string, unknown>
    requiredTools?: string[]
    forbiddenTools?: string[]
    requiredSources?: string[]
    maxSteps?: number
    maxCost?: number
  }
  tags: string[]
}
```

数据集至少覆盖：

- 正常任务和高频任务；
- 模糊请求、缺少信息与相互冲突的要求；
- 工具超时、空结果、限流与部分失败；
- 无权数据、高风险写操作和审批被拒绝；
- 直接提示注入、网页/邮件中的间接注入；
- 历史上真实发生过的生产问题。

每修复一个生产问题，先将它转为回归样本，再修复实现。

## 3. 评分器如何组合

- **确定性规则**：Schema、数字、字段、工具名、权限与代码测试，最可靠。
- **语义相似度**：适合容许多种表达的短答案，不能单独判断事实真伪。
- **LLM-as-judge**：适合评估完整性、相关性和风格，需要清晰 rubric，并用人工样本校准。
- **人工评审**：用于高风险决策、新场景和评分器分歧样本。
- **生产指标**：用真实的完成、撤销、升级人工和用户修正信号校验离线评测。

对生成式评分器也要做版本管理，固定模型、指令、采样参数和 rubric。

## 4. 从威胁建模开始

列出系统中的：

1. **资产**：用户数据、密钥、资金、发布权限、企业知识。
2. **信任边界**：用户输入、网页、邮件、文档、MCP Server、子 Agent。
3. **能力**：哪些工具能读数据，哪些能改状态。
4. **攻击目标**：窃取数据、越权操作、持久化污染记忆、消耗资源、隐藏轨迹。

安全不能建立在“模型应该能识别恶意指令”上。模型层防御只是其中一层，权限、沙箱、输入校验、审批和网络隔离必须在应用与基础设施层执行。

## 5. 提示注入：把数据当成了指令

提示注入有两个高频入口：

- **直接注入**：用户在对话中要求忽略系统规则。
- **间接注入**：Agent 读取的网页、文档、邮件或工具返回中藏有恶意指令。

防御组合：

- 将外部内容标记为不可信数据，与系统指令明确分隔；
- 不让读取高风险内容的解析器同时拥有写工具；
- 对 URL、文件、数据库和工具设置白名单和最小权限；
- 重要写操作要求基于具体参数的即时审批；
- 连续检测异常工具序列、数据外发和权限升级尝试；
- 对外部内容进行长度、类型、编码和重定向限制。

参考 [OWASP LLM Prompt Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)。

## 6. 最小权限与最小自主性

对每个 Agent 和每个工具限制：

- 可访问的租户、用户、资源和字段；
- 读、写、删除、对外发送的独立权限；
- 可访问的网络域名和端口；
- 单次金额、数量、速率、步数和总费用；
- 凭证的有效期和可撤销性。

即使最终使用的是同一个后端 API，也应向 Agent 暴露更细粒度、风险可分级的业务工具。

## 7. 发布门禁

每次更换模型、提示词、工具描述、检索器或工作流，都运行同一套回归测试：

- [ ] 核心任务成功率不低于基线。
- [ ] 高风险安全样本 100% 通过。
- [ ] 未授权工具调用数为 0。
- [ ] P95 延迟和平均成本在预算内。
- [ ] 随机抽样人工评审无新的高风险退化。
- [ ] 可以按版本快速回滚模型、指令和工具集。

## 8. 一组实用指标

```text
任务成功率 = 满足所有关键验收条件的任务数 / 总任务数
工具成功率 = 成功工具调用数 / 全部工具调用数
一次通过率 = 无重试、无人工修正就成功的任务数 / 总任务数
单成功任务成本 = 总费用 / 成功任务数
安全拦截率 = 被正确拦截的攻击样本数 / 攻击样本总数
```

指标要按任务类型、模型版本、工具版本和用户群分组观察，否则总平均值会掩盖某一类任务的严重退化。
