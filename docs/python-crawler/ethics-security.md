# 合规、伦理与安全

能通过技术访问，不代表有权采集、保存、分析或再发布。法律与合同要求会因地区、数据类型和用途而不同；高风险项目应让法务、隐私和安全负责人参与评审。

## 四层边界

| 层级         | 要检查什么                                  |
| ------------ | ------------------------------------------- |
| 访问授权     | 公开页面、账号权限、API Scope、站方书面授权 |
| 自动访问规则 | robots、速率限制、服务条款、API 政策        |
| 数据权利     | 版权、数据库权利、个人信息、商业秘密        |
| 后续用途     | 保存期限、画像、训练、共享、再发布和删除    |

任一层不清楚，都应暂停并确认，而不是先抓取再处理。

## robots.txt

[RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html)定义了 Robots Exclusion Protocol，允许服务方表达自动客户端对 URI 的访问规则。它要求爬虫遵守匹配规则，但也明确说明这些规则不是访问授权机制。

Python 标准库提供 `urllib.robotparser`：

```python
from urllib.robotparser import RobotFileParser

USER_AGENT = "CatalogSync"
BASE_URL = "https://example.com"

robots = RobotFileParser()
robots.set_url(f"{BASE_URL}/robots.txt")
robots.read()

target = f"{BASE_URL}/catalog/page/1"
if not robots.can_fetch(USER_AGENT, target):
    raise PermissionError(f"robots.txt 不允许访问: {target}")

delay = robots.crawl_delay(USER_AGENT)
request_rate = robots.request_rate(USER_AGENT)
```

生产环境要为 robots 获取设置超时、缓存和错误策略，并按 RFC 与组织政策处理不可达情况。若站方另有明确接口政策，以更严格的要求为准。

## 尊重站点控制

遇到以下信号应暂停或降速：

- 401、403 或登录挑战。
- 429、`Retry-After` 或速率限制响应头。
- 验证码、人机验证或风险确认页。
- robots 或服务条款变化。
- 站方主动联系、封禁或撤回授权。

不要通过轮换账号、伪造身份、绕过验证码、隐藏自动化特征或切换大量代理来规避限制。正确路径是使用官方 API、申请权限、降低负载或停止采集。

## 数据最小化与隐私

- 只采集实现明确目的所需字段。
- 在采集前定义合法用途、访问角色和保留期限。
- 不默认采集邮箱、电话、精确位置、账号标识等个人信息。
- 日志、测试 fixture、截图和原始 HTML 同样纳入隐私治理。
- 支持来源撤回、用户删除和下游派生数据同步删除。
- 聚合结果仍可能重新识别个人，需要单独评估。

不要把“公开可见”当作“无限期集中存储和画像”的同义词。

## 版权与再发布

事实、页面结构、图片、文章、评论和数据库集合可能受到不同权利保护。即使获准自动访问，也要确认：

- 是否允许保存全文，还是只能保存链接和少量元数据。
- 是否允许商业使用、模型训练、搜索展示或再次分发。
- 是否需要署名、来源链接和更新 / 删除同步。
- 数据许可证能否与下游产品的许可证兼容。

## SSRF 与网络边界

爬虫会主动访问 URL，因此很容易成为 SSRF 通道。最安全的做法是允许列表：

- 只允许明确批准的 `https` 域名、端口和路径。
- 每次重定向都重新检查目标，而不是只检查初始 URL。
- 阻止环回、私网、链路本地、云元数据和内部服务地址。
- 防范 DNS 重绑定：连接时验证实际解析地址。
- 不接受用户随意提交 URL 后由高权限爬虫访问。
- 爬虫运行身份不能访问不必要的内网和云权限。

仅检查字符串中是否包含 `localhost` 远远不够；URL 混淆、IPv6 和重定向都可能绕过简单检查。

## 不可信响应

下载到的任何内容都可能是恶意输入：

- 限制响应头、响应体、重定向次数和解压后大小。
- 解析 XML 时禁用外部实体和网络访问。
- 压缩包防止 Zip Slip、压缩炸弹和超大文件数量。
- 不执行页面脚本、宏、二进制或仓库附带代码。
- 文件类型不能只相信扩展名和 `Content-Type`。
- 图片、PDF 和文档解析放入资源受限的隔离环境。

浏览器自动化运行在容器或沙箱中，并使用低权限账号。不要为了方便给爬虫挂载生产密钥或整个内部文件系统。

## CSV 与公式注入

以 `=`, `+`, `-`, `@` 开头的文本被电子表格打开时，可能被解释为公式。若数据会进入表格软件：

- 优先使用不会执行公式的查看方式。
- 导出层对危险前缀进行显式处理。
- 保留原始值和处理记录。
- 不鼓励用户忽略外部内容安全警告。

CSV 转义只能解决分隔符和换行，不能自动防止公式注入。

## 凭证与会话安全

- 使用专用低权限服务账号，不复用个人管理员账号。
- Token、Cookie、`storage_state` 和代理凭证进入秘密管理系统。
- 对凭证设置过期、轮换、吊销和使用审计。
- 日志与错误追踪默认清除认证头和 Cookie。
- 多租户数据使用独立会话、存储前缀和权限边界。

## 依赖与供应链

- 固定 Requests、解析器、浏览器和 Scrapy 等依赖版本。
- 从可信索引获取包，验证锁文件和构建产物。
- 定期扫描漏洞，但升级后先运行 fixture 回归。
- 浏览器和解析库处理不可信输入，安全更新优先级较高。
- 容器使用非 root 用户，并限制网络、文件和系统调用。

## 项目审批清单

- 数据所有者、访问授权和用途已书面确认。
- 官方 API / 导出不可用或不能满足需求的原因已记录。
- robots、服务条款、版权和隐私完成评审。
- 域名、路径、速率、并发、总量和运行时间有硬上限。
- 不包含访问控制、验证码或风险确认绕过。
- 有联系人、暂停开关、删除流程和站方投诉处理方式。
- 原始数据、日志、凭证和测试样本有访问控制与保留期。
- 任务退役时会撤销凭证、停止调度并清理数据。

一个专业的爬虫应该让数据提供方、维护者和下游使用者都能理解它为何访问、访问多少、保存什么，以及如何让它停止。
